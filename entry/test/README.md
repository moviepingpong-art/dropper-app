# 申込書ドロッパー — 中核の確認用

`entry-xlsx.js`（xlsx の読み書き）・`entry-roster.js`（名簿・名前の突き合わせ・書き込む値）・
`entry-ai.js`（欄の対応づくり）を、画面を通さずに Node で確かめるためのものです。

## 画面を手元で試す

```
python -m http.server 8765 --bind 127.0.0.1        （リポジトリの直下で）
```

`http://127.0.0.1:8765/entry/` を開き、`fixtures/` の様式と名簿を入れる。
AI を呼ばずに試すときは、ブラウザのコンソールで `window.fetch` を差し替え、Gemini への POST に
`expected-maps.json` の答えを返させる（2026-09-15 はこの形で①〜⑥を通した）。
`entry/test/out/local-typed.xlsx`（`run.js` が作る、本物の百万石に架空の名前を書いた版）も入れられる。

## 使い方

```
node entry/test/make-fixtures.js                          試験用データを作り直す（fixtures/）
node entry/test/run.js                                    確かめる。落ちたら終了コード 1
powershell -ExecutionPolicy Bypass -File entry/test/excel-check.ps1   本物の Excel で開いて確かめる
```

`excel-check.ps1` は `run.js` が `out/` に書き出したファイルを開きます。先に `run.js` を流してください。
Excel の入っている PC でだけ動きます。

### 本物の Gemini で確かめる（live-ai.js）

`run.js` は**偽の応答**で「当てはめ方」を確かめます。**説明文（プロンプト）が AI に伝わるか**は、本物で試すしかありません。

```
$env:GEMINI_API_KEY = '（自分のキー）'; node entry/test/live-ai.js     （PowerShell）
```

- **キーは環境変数からだけ読みます。** ファイルに書かない・コミットしない
- 送るのは架空の試験用データを伏せ字にしたものだけ。送る直前に関所（`guard`）も通ります
- 期待する答えは `expected-maps.json`（`run.js` と共用）。AI の答えは揺れるので、落ちたら差分を見て、
  プロンプトを直すか、期待が厳しすぎるかを判断してください
- `prompt()` を直したら流すこと。無料枠を1回あたり3〜4リクエスト使います

## 何を確かめているか

| # | 内容 | なぜ |
|---|---|---|
| 1 | 名簿の読み取り | 生年月日の書き方（Excelの日付・`S27.5.10`・`昭和30年2月28日`・`平成元年`・`19600303`）、性別の書き方（男性・M・F）、電話の先頭の0、〒と都道府県の切り分け |
| 2 | 名前の見つけ方 | 表記ゆれ（髙/高、﨑/崎）・同姓同名・誤字の疑い・姓と名が別の欄・同じ人が2回 |
| 3 | **伏せ字に名前が残らない** | AI に送る前の形に、名簿の名前・姓・名が1つも入っていないこと |
| 4 | **書き換えたセル以外が変わらない** | ZIP の中の部品は圧縮済みのバイト列まで同じ。書いたシートも、書いたセルを除けば同じ |
| 5 | 行とセルの並び | 崩れると Excel が開けない |
| 6 | 本物の Excel で開ける | 修復なしで開け、値が期待どおり |
| 7 | AI の欄の対応 | 行の型を当てはめた結果が、手で書いた対応と一致する。変な答え（無い種類・ありえない列・見出しの上）を捨てる。**名前が紛れ込んだら送らずに止まる（通信0回）**。503 で予備のモデルへ、429 の区別。同じ様式なら名前が違っても同じ鍵 |

## 試験用データ（fixtures/）

**人・団体・住所・電話番号はすべて架空です。本物の名簿は絶対に置かないでください（public リポジトリ）。**
`make-fixtures.js` が作ります。日時を固定しているので、作り直しても同じバイト列になります。

| ファイル | 形 | 通す道 |
|---|---|---|
| `roster.xlsx` / `roster.csv` | 架空の名簿14人 | 罠: 同姓同名・生年月日が空・性別が空・年齢が古い・電話が数値 |
| `form-a-all-fields.xlsx` | 全項目型。1人1行 | セルが無いところへ書き込む。名簿に無いフリガナを知らせる |
| `form-b-pairs.xlsx` | 百万石型。2人1組・結合セル・生年月日が元号/年/月/日 | 罫線つきの空セルを置き換える。合計年齢を結合セルに書く |
| `form-c-split.xlsx` | 姓と名が別欄・男女の列に○・都道府県が別欄 | 式のセルを上書きしない。開いたときに計算し直させる |

様式には「幹事が名前だけ書いた」状態で、わざと崩した名前が入っています。

## 本物の様式で試す（local/）

大会の申込書は主催者の文書なので、リポジトリには入れません。
`entry/test/local/` に置くと `run.js` が拾います（`.gitignore` 済み）。無ければその項目だけ飛ばします。
いまは百万石オープンの申込書（ファイル名に「百万石」を含む `.xlsx`）を探します。

**local/ にも本物の名簿は置かないこと。** 試験は架空の名簿で流します。

## 踏んだ罠

### 本物の Gemini で分かったこと（2026-09-15、live-ai.js を4回。主モデルが 503 続きで、ほぼ軽量版の結果）

- **★ AI が行を1つずらすと、黙って間違った申込書ができる。** 本物の百万石の様式（見出しが「生年月日」の下に
  「年・月・日」の2段）で、生年月日の4欄を名前の1行下と答えた。書き込み先は2人目の空欄なので
  「文字の入った欄には書かない」をすり抜ける。**名前の行の間隔から1人ぶんの行数を測り、それ以上ずれた指示は書かない**
  （`offset-crosses-person`）。説明文に頼らず、ツールの側で止めること
- **★ 予備のモデルに版番号つきの名前を使わない。** `gemini-2.0-flash` は提供が終わって 404。主モデルが 503 のとき必ず失敗した
- AI は列を「C14」「C:E」の形で書いてくることがある（氏名が C14:E14 の結合セル）。先頭の英字を採る
- 軽量版は「男」「女」の列の片方を落としたことがある（`gender-mark-unpaired`）
- 記入例の無い欄の書き方（元号を「昭和」か「S」か）や、名簿から埋められない欄に団体の欄を挙げるかは揺れる。
  どちらも誤りではないので、`live-ai.js` では extras を NG にしていない
- 様式に書き方の手がかりが無いと、AI は説明文の既定（和暦）を選ぶ。期待値のほうを西暦にしていて NG になった。
  **期待値を甘くするより、様式に記入例を置いて手がかりを与える**直し方にした

- **★ 漏れを探す確認は、説明文ではなくデータの部分に向ける**（2026-09-15）。
  プロンプトの説明に書き方の例「1950/4/1」があり、「生年月日が載っている」と誤って落ちた。
  確かめる範囲は `■ シート` から後ろ。足した確認は、わざと漏らして見抜けることを確かめてある
- **★ AI の答えが JSON の「文字列」や「配列」でも、JSON としては正しい**（2026-09-15）。
  `extractJson` が通してしまい、空の対応が成功扱いになっていた。オブジェクト以外は `bad-json` で止める

- **★ 壊したファイルで確認スクリプトを試すときは、壊せたことを先に確かめる**（2026-09-15）。
  存在しないセルを狙って置き換えが空振りし、壊れていないファイルを「Excel は壊れていても開く」と
  読み違えかけた。さらにシェルのヒアドキュメントで JS を書き出したら `\\` が `\` に潰れ、
  正規表現が別物になっていた。スクリプトはファイルとして書き、置き換えの前後を比べること
- **★ `excel-check.ps1` の `Workbooks.Open` に `[Type]::Missing` を並べない。**
  すべてのファイルが「開けない」になる。引数は3つまでにしてある
- **★ `.ps1` は英数字だけで書く。** Windows PowerShell 5.1 は BOM の無い `.ps1` を CP932 で読む。
  日本語の期待値は `out/expect.json`（UTF-8）から読む
