# 予定表ドロッパー — 抽出の確認用データ

`schedule-parser.js`（通常モードの抽出）を、**実機で取れたOCRテキスト**に対して流すためのものです。

## なぜ要るか

GoogleドライブのOCRは表を**「1セル＝1行」**に分解して返します。その並びは予定表ごとに違い、
ローカルのPDFテキスト抽出（pypdf 等）とも別物です。つまり**実機のOCR結果でしか確かめられません**。

過去に、片方の予定表だけを見て直した結果、もう片方の形式を見落としたことがあります。
`schedule-parser.js` を触ったら、**修正の前後でこれを流し、件数と中身を見比べてください**。

## 使い方

```
node schedule/test/run.js                 全部
node schedule/test/run.js tleague         1つだけ
```

自動で合否を出すテストではありません。**目で見比べるためのもの**です。
件数が目安と変わっていたら、その場で知らせます。

## 入っているデータ

| ファイル | 元 | 件数 | ここで確かめたいこと |
|---|---|---|---|
| `ocr-tleague.txt` | ノジマTリーグ 2026-2027シーズン日程表（**抜粋**） | 17 | 都道府県と会場が別の列。**チーム名が「静岡」「京都」「岡山」と県名に一致する**ため、県名だけの行を素朴に拾うと行事名が `KM東京 -` だけになる |
| `ocr-zenkoku-shikoku.txt` | 令和8年度 全国大会予定表 ＋ 四国大会予定表（全文） | 42 | 場所の書かれ方が2通り混在。`埼玉県 深谷市他`（1行）と `高知`＋`高知県民体育館`（2行）。`未定` の行と次の表の見出しで区切れているか |

`ocr-tleague.txt` は抜粋です。全150試合のうち、判断の難しい行（台湾開催、表の境目、数字を含む会場名、
1〜3月＝翌年になる行）を残しています。

## 新しいデータの取り方

うまく読めない予定表が見つかったら、その場で採取できます。予定表ドロッパーで**通常モードで**
読み込んだあと、ブラウザのコンソールで:

```javascript
copy(window.lastOcrText)
```

クリップボードに入るので、`ocr-〇〇.txt` として保存し、`run.js` の `FIXTURES` に1件足してください。

## 出どころについて

どちらも一般に公開されている大会日程表です。読み取りの確認に必要な範囲だけを置いています。
